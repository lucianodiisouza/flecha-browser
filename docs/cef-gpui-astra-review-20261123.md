# Flecha rewrite decision brief

**23 November 2026, Stockholm.** Build the shell in GPUI and give each live tab an off-screen CEF browser. Keep the existing Flecha executable and profiles available until the replacement passes the owner's workflows. Two release promises need decisions before bulk implementation: Google's published policy excludes CEF sign-in, and CEF's off-screen style lacks Chrome's extension toolbar. Neither follows from using the latest Chromium. [Google's browser requirements](https://developers.googleblog.com/guidance-to-developers-affected-by-our-effort-to-block-less-secure-browsers-and-applications/) · [CEF maintainer on extensions](https://github.com/chromiumembedded/cef/issues/3859)

## Engine and toolkit pins

**CEF and cef-rs, high confidence.** The official stable index lists **CEF 158.0.3+g8c29be2+chromium-158.0.8127.18**, Chromium milestone 158, for Linux x64, macOS arm64 and Windows x64. Its binaries were posted on November 20. Flecha's source pin is 158.0.8127.2. Tauri's latest published `cef` crate is **156.7.0+156.0.31**, released November 19. Open PR #520 already generates **158.0.0+158.0.3** for all target architectures at `32d6bc558545933eb1b4620aac4bc4799299c129`. Pin that revision for spikes and verify the loaded binary and C API hash. Re-resolve the stable index and matching bindings at implementation and release. [CEF build index](https://cef-builds.spotifycdn.com/index.json) · [cef-rs releases](https://github.com/tauri-apps/cef-rs/releases) · [M158 bindings and manifest](https://github.com/tauri-apps/cef-rs/pull/520/files) · [Flecha pin](/home/timpan4/dev/flecha-browser/chromium/CHROMIUM_VERSION)

The helper downloads the target's minimal binary archive from Spotify's CEF CDN, verifies its indexed SHA-1 and extracts it. The build script supports a validated `CEF_PATH` cache or its own output directory. Lock the binding revision, CEF build and artifact digest together in CI. **GPUI, high confidence.** Zed's published `gpui` is 0.2.2 from October 2025. Its README describes macOS and Linux. Current upstream supports standalone apps through `gpui_platform::application()`, Win32/DirectWrite with D3D11, macOS Metal with `font-kit`, and native Wayland/X11 with wgpu Vulkan or GL. GPUI is pre-1.0 with frequent breaking changes. Pin `gpui` and `gpui_platform` to the same tested Zed revision, initially `f126950f9d3b62666f97437ae5d4ccac2272c4db`. ## Putting web content inside GPUI

**High confidence on APIs, medium on integration until tested on hardware.** Native children have their own stacking and input surfaces. A GPUI overlay cannot reliably cover or clip them through its ordinary scene graph. Windows supports an HWND child. Linux supports an X11 child, including under XWayland. Stock CEF can create a Wayland top-level window, but embedding it into an existing Wayland parent remains open. macOS supports an NSView child and explicitly forces Alloy style when a parent view is supplied. Use native children as diagnostic controls. Use OSR for the product's shared composition model. [CEF runtime styles](https://github.com/chromiumembedded/cef/blob/8c29be2/include/internal/cef_types_runtime.h) · [macOS contract](https://github.com/chromiumembedded/cef/blob/8c29be2/include/internal/cef_types_mac.h#L148) · [Wayland embedding demonstration against stock CEF](https://github.com/chromiumembedded/cef/issues/2804#issuecomment-5160885335)

Start with CEF's BGRA `OnPaint` as a correctness reference. Accelerated `OnAcceleratedPaint` provides callback-scoped resources. Reopen each frame, copy into a Flecha-owned GPU texture, and ensure the source read finishes before returning. cef-rs's `accelerated_osr` helper already performs that copy and wait. Import failure needs an explicit software-mode recovery. Never queue the borrowed CEF handle for GPUI's next frame. [CEF paint contract](https://github.com/chromiumembedded/cef/blob/8c29be2/include/cef_render_handler.h#L151) · [cef-rs import contract](https://github.com/tauri-apps/cef-rs/blob/32d6bc5/cef/src/osr_texture_import/mod.rs)

| Platform | GPUI renderer work |
|---|---|
| Linux Wayland and X11 | Import dma-buf planes with their fds, stride, offsets, format and modifier on the matching Vulkan adapter. GPUI's wgpu renderer skips surface batches. Add a sampled-texture draw with clipping and transforms. Unify wgpu sources first: Zed pins a Git revision, cef-rs requests registry v30. Test NVIDIA resize and GPU mismatch explicitly. [CEF plane format](https://github.com/chromiumembedded/cef/blob/8c29be2/include/internal/cef_types_linux.h) · [GPUI draw site](https://github.com/zed-industries/zed/blob/f126950f/crates/gpui_wgpu/src/wgpu_renderer.rs#L1545) · [Zed lock](https://github.com/zed-industries/zed/blob/f126950f/Cargo.lock#L20645) · [NVIDIA frame-ordering report](https://github.com/chromiumembedded/cef/issues/4313) |
| macOS arm64 | Import the IOSurface on Metal. GPUI's existing surface path accepts a bi-planar YCbCr pixel buffer. [Metal draw site](https://github.com/zed-industries/zed/blob/f126950f/crates/gpui_apple/src/metal_renderer.rs#L1237) |

Each GPUI web element owns viewport, device scale, focus, screen coordinates and popup placement. Forward M158 keyboard/mouse/wheel, touch and capture loss. Integrate composition, commit, cancel and candidate-window bounds with native IME. Draw select menus from `PET_POPUP` with translated hit tests. JS `window.open` creates a distinct browser and must preserve opener semantics. Bridge native drag source and target, clipboard and context menus. OSR emits an accessibility tree, while the host must expose platform objects and route assistive actions. Connect CEF updates to GPUI's AccessKit tree. Native DevTools opens a separate Chrome-style window. Per-tab Chrome DevTools Protocol (CDP) calls work without opening a remote debugging port. If every developer-tools control must also use GPUI, scope a separate CDP frontend. **Google sign-in is a release gate. High confidence on policy, unverified on this binary.** Google explicitly excludes CEF-based browsers and restricts embedded OAuth user agents. A human login succeeding once establishes observed behavior only. System-browser OAuth can authorize Flecha's own client, but cannot establish a Gmail browsing session in a Flecha Space. Chrome Sync is a separate product. ## Implementation plan and acceptance

**Architecture, medium confidence pending integration.** `flecha-core` owns durable IDs, versioned storage, migration and session restore. `flecha-cef` owns live browser/context handles and thread-affine callbacks. `flecha-ui` owns GPUI windows, focus and chrome. `flecha-surface` performs texture import and composition. `flecha-services` owns import, discovery and the opt-in authenticated loopback MCP service. Keep the CEF browser process with GPUI and use sandboxed CEF renderer/GPU/utility processes, including macOS helper bundles. Post typed events keyed by durable tab ID and live browser generation to the UI thread. Use frame-scoped IPC only for renderer work. Never expose privileged shell commands to page JavaScript. Integrate CEF's external pump on GPUI's main thread, respecting scheduled work, its documented periodic wake-up and reentrancy. Retain the Node browser/Arc importers behind private stdio while Rust replaces native messaging. Retire the sidecar when Rust passes merge/append, preview and onboarding fixtures. Preserve MCP's background agent folder, focus isolation and token boundary. [CEF process layout](https://github.com/chromiumembedded/cef/blob/8c29be2/docs/tutorial.md) · [Pump contract](https://github.com/chromiumembedded/cef/blob/8c29be2/include/cef_app.h) · [Existing host protocol](/home/timpan4/dev/flecha-browser/chromium/native-host/protocol.ts)

1. **Resolve release gates after plan approval.** Build the exact M158 pair in a disposable profile. A human tests direct Gmail login, MFA, sign-out/relogin, third-party Google OAuth, restart and isolated accounts against today's Flecha control. Use a purpose-created account, truthful branding, MFA entered by its owner, automation off and no credential logging. Record outcomes without account identifiers. A rejection fails parity. A pass still requires Google confirmation or the owner's explicit acceptance of unsupported sign-in. In parallel test Store install, requested permissions, popup action on the active page, extension management, password save/fill and print in windowed Chrome and intended OSR.
2. **Prove the compositor and input.** On the owner's native Wayland/NVIDIA setup, X11, Apple Silicon and Windows, show a moving frame counter, resize, switch DPI, overlap Peek, use select menus, IME and file drag, and navigate web plus shell with the platform screen reader. Verify frames, clicks, focus and accessibility actions reach the correct tab. Compare CPU/GPU and frame timing against existing Flecha on identical workloads. A blank, stale or misrouted frame fails. [Existing benchmark](/home/timpan4/dev/flecha-browser/chromium/tests/perf-bench.mjs)
3. **Build a vertical slice.** Open, split, Peek, promote, transfer, close and restart. Separately verify shared and isolated cookies and local storage, private-state disposal and unchanged source profiles. Import from a copy via a versioned, retry-safe transaction. Reuse fixtures and adapt the native X11 harness's shell-DOM assertions to GPUI semantics. Add real Wayland, macOS and Windows checks. [Existing workflow and preservation evidence](/home/timpan4/dev/flecha-browser/continuation-handoff.md) · [Native harness](/home/timpan4/dev/flecha-browser/chromium/tests/native-workflows.mjs)
4. **Parallelize after approval.** Give GPT-6.2 Sol agents the fixture-driven store, GPUI shell and import units. Give Opus 5.5 agents the CEF lifecycle and platform renderer units. One owner maintains the typed event contracts. Integrate each unit through the same vertical slice. Release only after signed and notarized macOS helpers, Linux sandbox, Windows bootstrap, restart/update/rollback and download safety pass on installed packages. Include license notices and verify shipped codecs. Secure owner decisions on separate native DevTools, extension fidelity and VSR. ## Ranked risks

1. **Critical: Google policy.** Requires a product decision even if the test succeeds.
2. **Critical: extension and browser UI parity.** Stock Alloy lacks extension anchors and print preview. A successful Chrome-style control cannot qualify the GPUI path.
3. **High: profile loss or cross-Space leakage.** Migrate beside the original. Test crash/retry, keychain-bound data, private teardown and agent-extension isolation before cutover.
4. **High: rendering, input and accessibility.** Gate on hardware, screen-reader actions and frame freshness. Xvfb alone covers none of the native Wayland/NVIDIA path.
5. **High: security updates and patched binary ownership.** Track M158 binding lag, GPUI changes, download warnings and VSR patches. Qualify sandboxed packages and exercise a subsequent upstream update before replacing the working distribution.

Confidence is high in documented constraints and medium in the proposed implementation until the spikes run. This review inspected sources and distribution records. It did not build or run the replacement.
